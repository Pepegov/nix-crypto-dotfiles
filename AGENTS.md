# Руководство для агентов

## Назначение проекта

Этот репозиторий описывает минимальную NixOS VM `crypto-vm` для ограниченных
криптовалютных операций и работы с Trezor. Конфигурация уменьшает поверхность
атаки, но не делает недоверенный хост или гипервизор доверенным. При изменениях
сохраняйте этот принцип: меньше сервисов, пакетов, интеграций с хостом и
постоянного состояния.

Перед изменением модели безопасности прочитайте `README.md`, `SECURITY.md` и
`HOST-CHECKLIST.md`.

## Структура

- `flake.nix` - входы и выход `nixosConfigurations.crypto-vm`.
- `nixos/hosts/crypto-vm/` - конфигурация хоста, аппаратная база и разметка
  диска.
- `nixos/modules/` - изолированные настройки безопасности, сети, рабочего
  стола, браузера и Trezor.
- `home-manager/crypto.nix` - пользовательские пакеты и настройки XFCE для
  пользователя `crypto`.

Предпочитайте небольшой тематический модуль вместо несвязанного роста
`configuration.nix`. Комментарии должны объяснять именно компромисс
безопасности или причину намеренно отключенной возможности.

## Обязательные ограничения безопасности

- Никогда не добавляйте в Nix, Git, скрипты, переменные окружения или `flake`
  seed-фразы, приватные ключи, recovery material, пароли, API-ключи, 2FA-коды,
  LUKS-пароли и иные секреты.
- Не добавляйте shared folders, virtiofs, 9p, clipboard/drag-and-drop
  интеграции, QEMU guest agent, USB auto-redirection или USB storage без явного
  запроса пользователя и обновления документации о рисках.
- Не включайте сервисы, фоновые демоны, дополнительные браузерные расширения,
  сторонние binary caches или доверенные Nix-ключи без явного обоснования и
  проверки воздействия на threat model.
- Для разрешенного браузерного расширения закрепляйте официальный Chrome Web
  Store ID в `nixos/modules/browser.nix`, сохраняйте блокировку всех остальных
  расширений и обновляйте описание профиля Brave в `README.md`.
- Автозапуск Trezor Suite допустим только после явного USB passthrough в VM и
  не должен включать постоянный `trezord` или другой bridge-демон. Он должен
  работать и для устройства, переданного до входа пользователя в Xorg-сессию.
- Для кошельков предпочитайте пакеты из закрепленного `nixpkgs`. Не добавляйте
  download-and-run скрипты, императивные установки или автоматическое получение
  исполняемых файлов при активации.
- Локальные заметки могут быть удобны для несекретной информации, но никогда
  не должны использоваться для seed-фраз, паролей, recovery material или иных
  секретов.
- `nixos/hosts/crypto-vm/disco.nix` описывает уничтожающую разметку диска.
  Не запускайте `disko` в режиме `destroy`, `format` или `mount` без прямого
  запроса пользователя и подтвержденного целевого диска.

## Проверка изменений

После изменения Nix-файлов сначала выполняйте безопасную проверку без сборки:

```sh
nix flake check --no-build
```

Если изменение затрагивает конфигурацию VM, при доступности зависимостей также
проверяйте оценку или сборку целевой конфигурации:

```sh
nixos-rebuild build --flake .#crypto-vm
```

Не выполняйте `nixos-rebuild switch`, `nixos-install`, обновление флейка или
изменение lock-файла без явного запроса. Не заменяйте закрепленные входы и не
обновляйте `flake.lock` попутно с другой задачей.

## Изменения и документация

- Сохраняйте формат Nix: два пробела для вложенных атрибутов, короткие
  декларативные выражения и существующий стиль комментариев.
- При изменении пакетов, сервисов, USB, сети, браузерных политик или доверенных
  границ синхронно обновляйте соответствующие части `README.md`, `SECURITY.md`
  и, если применимо, `HOST-CHECKLIST.md`.
- Не откатывайте чужие изменения и не создавайте Git-коммиты без прямой команды
  пользователя.
